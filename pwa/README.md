# Juggluco Viewer PWA

Read-only React PWA для просмотра данных Juggluco. Production-приложение работает на том же HTTPS-origin, что и backend, по адресу `/viewer/`; API остаётся в `/v1/`.

PWA понимает два режима, которые сообщает `GET /v1/viewer/session`:

- `public` — открывается без входа и показывает сахар, прогноз и обезличенные отметки инсулина на графике; еда, ID событий и история редактирования не отображаются;
- `session` — сохраняет прежний вход по ключу и показывает владельцу сахар и события.

## Локальный запуск

Требуются Node.js и pnpm.

```bash
pnpm install
pnpm dev
```

Vite проксирует `/v1` на `http://127.0.0.1:8000`. Production-сборка:

```bash
pnpm typecheck
pnpm test:run
pnpm build
```

Готовые файлы появляются в `dist/`. Backend должен раздавать их под `/viewer/` с fallback на `/viewer/index.html` только для viewer-маршрутов.

## Дизайн

PWA использует ту же янтарную terminal-палитру, моноширинную типографику,
тонкие рамки и компактные контролы, что Android (`lifeprompt_design_tokens.xml`).
Тёмная тема выбрана по умолчанию; сохранённый выбор светлой или системной темы
остаётся в силе. Настройки открываются боковой панелью, главный экран помещается
в высоту окна с учётом безопасных отступов телефона.

SVG-график повторяет `ModernGlucoseChartView`: подсвеченная целевая зона,
цветные участки фактической линии, пунктирный прогноз с коридором неопределённости,
линия текущего времени и различимые маркеры инсулина. На диапазоне 6 часов
текущий момент расположен примерно на двух третях графика. Дополнительное место
справа — только свободное пространство: прогноз не продлевается за горизонт модели.
Сохраняются выбор периода, касание/проведение по точкам и управление клавиатурой.

После публикации установленная PWA предлагает «Обновить» для загрузки нового
app shell; показания продолжают обновляться независимо от обновления оформления.

## Установка на iPhone

1. Открыть `https://<ваш-домен>/viewer/` именно в Safari.
2. Нажать «Поделиться».
3. Выбрать «На экран “Домой”» и подтвердить.
4. Открывать Juggluco с появившейся иконки.

После первой успешной загрузки service worker сохраняет весь app shell: HTML, JavaScript, CSS, manifest и иконки. Последний успешный нормализованный снимок хранится в IndexedDB и показывается сразу при следующем запуске, в том числе без сети. iOS может очищать данные сайтов при критическом дефиците места; кнопка «Защитить offline-копию» запрашивает максимально доступный браузеру persistent storage.

## Безопасность локальных данных

- в режиме `public` экран входа, срок сессии и серверный выход отсутствуют;
- в режиме `session` ключ просмотра существует только в поле входа и теле `POST /v1/viewer/session` и не записывается в localStorage, IndexedDB или Cache Storage;
- в режиме `session` сервер создаёт HttpOnly cookie-сессию;
- все `fetch` используют `credentials: 'include'`, `cache: 'no-store'` и `redirect: 'error'`;
- service worker ограничен scope `/viewer/` и не может перехватывать `/v1/*`;
  конфигурация `NetworkOnly` дополнительно защищает API при будущих изменениях scope;
- IndexedDB содержит только нормализованный снимок, `savedAt` и режим доступа, нужный для безопасного offline-отображения;
- публичная кнопка удаления очищает только сохранённые показания, не удаляя установленный app shell, и приостанавливает их повторное сохранение до перезапуска;
- «Выйти и удалить данные» сразу скрывает показания, останавливает обновления и независимо очищает снимок и caches с namespace `juggluco-viewer`;
- завершение серверной сессии считается успешным только после ответа `DELETE /v1/viewer/session`; при сетевой ошибке PWA показывает отдельное состояние и кнопку повтора;
- до подтверждённого выхода сохраняется только безличный флаг `juggluco-viewer:logout-pending` без ключа, cookie или медицинских данных; он не позволяет после перезапуска молча загрузить данные через всё ещё активную cookie;
- ответ snapshot ограничен 12 МиБ до JSON-декодирования.

## Поведение данных

- сохранённый снимок отображается до сетевого обновления;
- после bootstrap-снимка PWA держит credentialed same-origin SSE-поток `/v1/viewer/stream` и запрашивает новый снимок сразу при новой glucose revision;
- heartbeat проверяется локальным watchdog; при разрыве EventSource автоматически переподключается, а foreground fallback опрашивает snapshot раз в 5 секунд до восстановления потока;
- при рабочем потоке остаётся редкая пятиминутная сверка, а возврат приложения на экран и событие `online` запускают её немедленно;
- компактные состояния `Онлайн`, `Подключение`, `Офлайн` и `Нет новых данных` не требуют ручной кнопки обновления;
- возраст показания тикает локально от серверных часов; heartbeat подтверждает связь, но никогда не делает старое показание моложе;
- перевод часов телефона назад больше чем на 5 секунд переводит показания и прогноз в fail-closed устаревшее состояние;
- прогноз скрывается, если его anchor старше 15 минут либо закончился его временной горизонт;
- фактический сахар показан сплошной линией в цветах Android: зелёный в цели 4,2–9,0 ммоль/л, коралловый ниже и янтарный выше; линия делится точно в местах пересечения порогов;
- прогноз использует те же цвета диапазонов, но остаётся пунктирным и сохраняет отдельный коридор неопределённости;
- быстрый инсулин (NovoRapid) и длительный инсулин (Tresiba) имеют разные цвета, формы маркеров и доступные подписи;
- разрывы фактической линии отмечают интервалы без показаний длиннее 10 минут.
